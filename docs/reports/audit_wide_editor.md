# 大屏（PC/平板）编辑页两栏场景适配审计报告（原版 vs Rust Web）

- 日期：2026-11-22
- 范围：宽视口（1024 横屏平板 / 1280 / 1440 / 1920）下编辑页全部模块：两栏布局本体细节、标题坞、正文排版、各块型与卡片在宽栏下的渲染、图库网格、斜杠面板与菜单锚点、对话框/底表/toast 摆位、拖拽拾起在大屏的表现。逐项核文本大小、字体、图标尺寸、胶囊/标签内距、上下左右间距。
- 不在范围：双栏机制本体（多列平衡流 vs 物理分栏）与媒体跨栏缺失的定性——已由 `audit_editor_full.md` A-1/A-2（H-8/H-9）裁定，本报告只给其大屏量化与新增子项，不重复深挖；标题胶囊内部（专项线）；列表页大屏（`audit_wide_list.md`）。
- 方法：原版相关代码完整读（editor-shell.css 全 630 行、styles/editor.css 标题钳制段、use-slash.js 定位段、editor.js 坞/Spread 内联段、editor.render.js 媒体渲染段、BackupView toast 段）；Rust 侧 styles 四件 + editor.rs 双栏渲染段 + blocks.rs 图库段通读。运行时：无头 Chromium 双边量测——Rust 侧用与生产逐字节一致的 dist 本地镜像（sw.js VERSION `0d1b9721a0`、wasm md5 `0d1b9721a09ecc6881746d0b76f99354` 与线上戳一致，构建源 HEAD fab40b5）；原版侧本地服务仓库根 Moment.html 实跑对照（1440 双栏/独立、1024 标题）。夹具 combined.zip（双栏混排 + 全块渲染测试）。探针：`wide_run_tmp.mjs`（Rust 侧四视口+独立+斜杠+底表+重进+拖拽）、`wide_orig_tmp.mjs`（原版侧）。**全部结论为 Chromium 口径，不代表 iOS 真机。**
- 证据等级：proven = 双边代码行号或代码+运行时实测；inferred = 代码路径推断。

## 不适配清单（按严重度排序）

### W-2（高）媒体块宽栏呈现面积：A-2/D-17 的大屏量化 + 图库双层边距新子项

跨栏缺失（A-2）与图库网格几何（D-17）为既有裁定，本条给四视口量化并新增一个子项：

| 视口 | 图库 tile：原版（整幅跨栏、2 列、定高 366） | 图库 tile：Rust（栏内、3 列方图） |
|---|---|---|
| 1024 | ≈458×366（网格宽 ≈920） | 109×109（实测） |
| 1280 | ≈588×366 | 150×150（实测） |
| 1440 | ≈666×366 | 176×176（实测） |
| 1920 | ≈666×366（spread 帽 1440） | 175×175（实测） |

- 原版依据：editor-shell.css:312-319 图库 `column-span: all`；editor.render.js:67-75 内层 grid `repeat(2,1fr)`、img 定高 366px、radius 22。
- Rust 现状：图库恒在物理栏内（A-2 结构性结果），`.gallery-grid` 3 列方图、radius 10（D-17 已记）。
- **新子项（proven，代码+四视口实测）**：Rust 图库左右内缩为 **72px/侧**，原版为 36px/侧。成因：外层 `.atomic[data-type="gallery"]` 带移植自原版的 `margin: 8px 36px`（editor.css:480），内层 `.gallery-grid` 又有自己的 `margin: 8px 36px`（editor.css:1376；blocks.rs:486-491 结构），两层叠加；原版内层 grid 为内联样式、无边距。实测四视口 grid 相对栏左缘内缩恒 72px。此子项窄屏同样存在（非大屏独有），与跨栏缺失叠加后进一步缩小 tile，修复归口建议并入 D-17 一并处理，避免两条线重复改图库边距。
- 同族量化（归 A-2，不另立项）：音乐卡/图文卡/图文行宽 = 原版整幅（992–1408）vs Rust 栏宽（实测 479.6 / 603.5 / 681 / 678）；图片块尺寸口径已对齐（自然宽居中、max-height 668，双边实测 400×300 与 308×668 两例一致），差异仅整幅居中 vs 栏内居中。

### W-1（中）标题字号 vw 缩放钳制对块标题失效（768–1167px 宽区间）

- 原版依据：styles/editor.css:380-383，spread 媒体内 `h1 { font-size: clamp(var(--md-heading-h2), 2.4vw, var(--md-heading-h1)) }`，h2/h3/h4 同族（2vw / 1.7vw / 1.45vw）。原版标题块渲染为真实 hN 元素（editor.render.js:44-47），钳制对块标题与 md 标题一并生效。令牌：h1 28 / h2 23 / h3 20 / h4 17px。
- Rust 现状：钳制规则已逐字移植（editor.css:452-455），但选择器瞄真实 h1–h4 元素；Rust 标题块是 `div.blk-h1…h4`（blocks.rs），不命中，恒令牌字号。规则只对 md 预览内的真实 hN 生效——**同一页里块标题与 md 预览标题在该区间会呈现两种字号**。
- 运行时实证（双边）：1024×768 原版真实 H1 computed = **24.576px**（恰 2.4vw）；Rust blk-h1 = **28px**（四视口恒定）。推得同区间差：h2 20.5 vs 23、h3 17.4 vs 20、h4 16 vs 17（公式+令牌，h4 夹具无样本未取活体读数）。
- 影响区间：视口宽约 768–1167px（横屏平板档）；≥1280 时钳制触顶、与令牌相等，无差异。严重度中：该区间标题系统性偏大 1–5px（h1 在 768–958 段差 5px），无功能影响。

### W-3（低）引用块大屏内距覆盖未命中 .blk-quote

- 原版依据：editor-shell.css 双栏细节段，spread 下 `blockquote { padding: 9px 12px }`（基线 10px 14px 的大屏收紧）。
- Rust 现状：同规则已移植（editor.css:885-892），但选择器瞄 `blockquote` 元素；Rust 引用块是 `div.blk-quote`，不命中——四视口实测宽屏恒 `10px 14px`（原版应为 9px 12px，Δ上下 1px / 左右 2px）。md 预览内 blockquote 走 `.md-preview.block > blockquote` 后代选择器，栏内命中、口径一致，仅块形态中招。

## 审计边界

- 全部为 Chromium 口径；iOS Safari/平板真机的 dvh、滚动条与触控行为未验。
- 反向链接区在夹具备忘中无入链、未取运行时读数（摆位已由 audit_editor_full A 片核一致：min(100%,720px) 居中，栏外整幅）。
- 表格、h4 两项为代码 proven、无活体读数（夹具缺样本）。
- 原版侧量测用其演示数据与现场输入（标题钳制一项为原版编辑器内现场生成并转块的真实 h1），未向原版导入夹具 zip（其恢复入口为程序化 file input，本轮以演示数据+现场输入取得所需读数，未深挖导入通道）。
