## 一、UIUX 角度

### U1. 隐藏手势零可发现性：左滑、长按拖拽、标题点按落点全靠用户自己发现

- **问题与证据**：现行三组核心手势没有任何界面提示——列表左滑置顶/删除、块长按拾起排序（拖拽规格阶段一自认「桌面零 affordance」、触屏同理）、长标题点按落点映射。首次播种的五篇示例备忘（`main.rs:302-363`，demo_exhibit/demo_home/demo_tools/demo_book/demo_music）全是生活内容，没有一篇教手势；设置页也没有手势说明入口。新用户（或换设备重装时）只能靠误触或口耳相传发现这些功能，功能做了等于没做。
- **建议做法**：① 种子区新增一篇「使用指南」备忘（可自由删除，与其余种子同级），用图文块演示左滑、长按拖动、斜杠菜单、双栏；② 首次进入编辑器时给一次轻量一次性提示（如长按块可拖动的气泡，本地标记看过即不再现，Diag 记一行）；③ 设置页「关于」区加一行手势速览入口，复用指南备忘。
- **成本**：小（文案五包同步是主要工作量，键数增加需走既有五包同提交规矩）。
- **预期收益**：已投入开发的三组手势功能真正被用起来；减少「不知道能拖」类支持成本。
- **优先级**：P1。

### U2. 空状态缺失：删光备忘、搜索零结果时只有空白

- **问题与证据**：`list.rs` 与五包语言文件内均无空库/零结果文案键（grep「暂无/无结果/empty」在列表渲染路径零命中）。用户删光全部备忘（含种子）后列表区空白、无任何引导；搜索无结果时同样空白，无法区分「没有这条笔记」和「加载出错」——后者在本地存储出问题时是真实歧义（Safari 站点数据事件证明过存储层会出事）。
- **建议做法**：补三态空状态，沿用玻璃语言与既有令牌：空库（图标 + 一句说明 + 「新建备忘」主按钮）、搜索零结果（显示当前查询词 + 「清除搜索」按钮）、加载失败（错误说明 + 「重试」+ 引导去诊断页）。文案五包同步。
- **成本**：小。
- **预期收益**：消除空白歧义，存储异常时用户能自助分流到诊断/备份恢复路径。
- **优先级**：P1。

### U3. 列表删除无撤销：左滑删备忘后恢复只能整包导入

- **问题与证据**：`list.rs` 内无任何 undo/撤销实现（grep 零命中）。左滑删除是单手势破坏性操作，误删一篇长备忘后，唯一恢复路径是导入旧 ZIP 整包回滚（validate-then-swap 会覆盖其后所有新编辑）。与之对照，编辑器内块级操作已有成熟撤销（600ms 合并、上限 100），列表层缺位，体验不一致。
- **建议做法**：删除改为软删 + 撤销窗口：删除后 toast 带「撤销」按钮（复用既有 toast 底表与 220ms 上滑，属用户已裁定保留的偏离面），窗口期（如 8 秒）内数据仅标记隐藏，超时才真删并落盘；窗口内杀进程重开不丢待删项（标记持久化）。不做回收站页面（二期再议）。
- **成本**：中（数据层加 deleted 标记需过一遍列表/搜索/导出过滤面，导出须排除待删项以保持 ZIP 格式口径）。
- **预期收益**：消除最高频的不可逆误操作；与「数据可靠性逐一保障」的红线直接对齐。
- **优先级**：P1。

### U4. 浅色模式次级文字对比度不达 AA（需用户裁定偏离 1:1）

- **问题与证据**：`tokens.css` 浅色 `--text-secondary: #8e8e93` 压在 `--primary-bg: #f2f2f7` 上，对比度约 3.0:1，低于 WCAG AA 小字 4.5:1；列表时间、分组标题、meta 行大量使用该色（字号多在 11–13px）。`--color-placeholder: #c7c7cc` 在白底约 1.6:1。深色侧 `--text-secondary: #98989d` 压纯黑约 5.9:1，达标——问题只在浅色。此色值与原版一致，加深即偏离 1:1，故单列待裁定。
- **建议做法**：二选一：① 仅浅色把 `--text-secondary` 加深一档至约 #6e6e73（约 4.9:1），其余令牌不动，视觉差异极小；② 维持现状并在本文件记录为知情取舍。占位符色维持（占位符在 WCAG 中豁免，但可顺带加深一档）。
- **成本**：小（①是一个令牌值 + 一轮截图核对）。
- **预期收益**：户外强光下时间/meta 可读性实质提升；老年/弱视可用性达标。
- **优先级**：P2（且需用户先裁定）。

### U5. 点击域系统性量测：已有 32px 级控件低于 44pt 指引

- **问题与证据**：`panels.css:158` `.seg-btn` 高 32px；`tokens.css` `--editor-menu-icon-slot-size: 24px`（图标槽）。做对的例子也有：待办勾选命中域已是 44×44（`editor.css:470/1354`，视觉圆 22px、命中 44px，正是本提案要推广的模式）。目前命中域是逐个组件随手定的，没有全量清单。
- **建议做法**：写一个探针批量量测全部可点元素的命中盒（列表行、胶囊、菜单项、段钮、图标钮），产出清单；<40px 的逐个评估，按「视觉尺寸不变、命中区外扩」模式（伪元素或 padding 补偿）补到 ≥40px，玻璃视觉零变化。量测探针留作回归资产。
- **成本**：中（量测小，逐个修要回归各面手势不冲突，尤其左滑与点按的命中竞争）。
- **预期收益**：误触率下降，单手握持时边缘控件更稳。
- **优先级**：P2。

### U6. 桌面键盘快捷键体系缺位

- **问题与证据**：全仓 `metaKey/ctrlKey` 仅出现在桥内虚拟选区的 Ctrl/Cmd+A/C/X 三键（`editor/bridge.rs:662-665`）。没有应用级快捷键：无法用 Cmd/Ctrl+K 或 `/` 聚焦搜索、Cmd/Ctrl+N 新建备忘、列表 ↑/↓ 选卡、Enter 打开。大屏/桌面场景（并行线正在适配）下，鼠标逐个点胶囊是唯一路径。
- **建议做法**：加一层应用级快捷键（搜索聚焦、新建、列表导航、返回），与桥内选区键、编辑器既有键位逐项核对冲突表后落地；设置页加「键盘快捷键」说明行（五包各加少量键）。
- **成本**：中（冲突核对是大头：contenteditable 内多数键已被编辑语义占用，安全键位不多）。
- **预期收益**：桌面重度使用效率；与大屏适配线互为表里。
- **优先级**：P2。

### U7. 无障碍语义层薄：aria 仅 18 处、图标钮多无可访问名

- **问题与证据**：全 web 源码 `aria-`/`role=` 合计仅 18 处。返回、菜单、头像、搜索、设置等图标型控件多为纯图标 div/span，读屏无名；`focus-visible` 显式焦点环只在待办勾选等少数处定义（`editor.css:474`），玻璃控件已有 `--glass-focus-ring`/`--md-focus-ring` 令牌却未普遍套用。已做对的部分：`prefers-reduced-motion` 全局熔断（`base.css:605`）、`prefers-reduced-transparency` 回退（`base.css:245`）均在位，不必重做。
- **建议做法**：一轮 a11y 扫荡：图标钮补 `aria-label`（新增少量 i18n 键，五包同步）；玻璃控件统一 `focus-visible` 环引用既有令牌；图片块 alt 取附件 manifest 既有文件名（数据现成）；对话框/底表补 `role="dialog"` 与焦点圈定。逐项过既有冒烟防回归。
- **成本**：中。
- **预期收益**：VoiceOver/键盘用户可完整走通四页主路径；顺带让自动化探针能按 role 定位、少依赖类名。
- **优先级**：P2。

### U8. 备份新鲜度无常驻呈现：唯一备份通道靠用户自觉

- **问题与证据**：数据只存本机 IndexedDB/OPFS，清站点数据即全丢（项目已有实证教训：清数据前必须先 ZIP 备份）。备份历史数据其实已存在（`settings.rs` BACKUP history 记录每次导入导出成败），但列表页与设置首页没有任何「上次备份距今多久」的常驻呈现，用户想不起备份这件事时界面不会提醒。
- **建议做法**：设置页「备份与恢复」行副文案改为动态：上次成功导出时间 + 距今天数；当「距上次导出 >7 天且期间有编辑」时，副文案转警示色并在备份页顶部加一条轻横幅。数据全取现成历史记录，不加新存储。
- **成本**：小。
- **预期收益**：把唯一的灾难恢复通道从「想起来才做」变成「界面会提醒」，直接降低全量丢数据风险。
- **优先级**：P2。

## 二、开发者角度

### D1. 标题/拖拽的专用探针没有进回归门（P0）

- **问题与证据**：`run_all_tests.sh` 的冒烟清单只有 15 个 smoke-* 套件。标题几何探针 `probe_title_geom.mjs`、拖拽探针 `probe_drag_sort.mjs`/`probe_drag_pickup.mjs`/`probe_drag_handle.mjs` 都不在其中——这两块是全项目返工轮次最多、行为最脆的面（标题四轮、拖拽两轮），其守卫探针却靠每批代理记得手动跑；某批漏跑即静默回退，门禁账面上仍全绿。
- **建议做法**：把三探针纳入 run_all_tests（新增 probe 段，失败即 FAIL=1）；标题探针的 CDP 组字路径较慢，可接受全量时长增加；同时在 TESTING.md 注明每个探针守的行为。
- **成本**：小（脚本清单 + 耗时调优）。
- **预期收益**：最脆两面的回归从「靠记性」变「靠门禁」，直接对冲历史教训（曾有 verify 未被 run_all_tests 调用、长期空转的前科）。
- **优先级**：**P0**。

### D2. Rust Web 没有 CI：全部门禁靠本地手动跑

- **问题与证据**：`.github/workflows/` 只有 `mynote-flutter.yml`，且触发路径限定 `native/**`。Web 侧 cargo test（90+ 项）、构建、verify 六节、15 套冒烟全靠本地执行——本机环境退化时（exec EPERM、内存不足均有前科）门禁质量随机器状态漂移，且换机/换人即无门禁。
- **建议做法**：新增 rust-web workflow：push/PR 触发 cargo test + build + verify_rustweb（无浏览器部分先行）；冒烟套件需 headless Chromium，作为第二 job 接入（playwright 缓存）。构建产物可作 artifact 留存，与 D3 归档衔接。
- **成本**：中（首次配缓存与浏览器环境最费时）。
- **预期收益**：门禁环境恒定、可复现；本地机器退化不再连带门禁可信度。
- **优先级**：P1。

### D3. 部署无归档、无回滚：坏构建上线只能改代码重发

- **问题与证据**：部署靠仓库外脚本 `~/workspace/mynote-ab/tools/deploy_api.py` 手动执行（且同目录 deploy_dir.py 已坏）；`build.sh` 每次 `rm -rf dist` 重建，历史构建零归档。线上核对（sw VERSION 与 wasm md5 逐字节对）目前靠人工执行、人工比对。若某构建上线后真机发现严重问题，没有「回到上一构建」的快路径，只能定位+修复+重新部署，窗口期用户持续受损（标题线多轮真机证伪史说明这不是假想场景）。
- **建议做法**：① 部署脚本前置一步：把当前 dist 按 sw VERSION 戳复制归档到 `releases/<version>/`（含构建戳、源提交号记录）；② 回滚 = 对任一归档目录重跑 deploy_api，一条命令；③ 部署后核对脚本化（抓线上 sw.js/wasm md5 与本地比对，不一致即红）。归档只留最近 10 个。
- **成本**：小。
- **预期收益**：坏构建的恢复时间从「修复周期」降到「一次重部署」；部署核对不再靠人眼。
- **优先级**：P1。

### D4. dist 体积：图标单文件 1.25MB、wasm 无 wasm-opt

- **问题与证据**：现行 dist 共 4.5MB：`mynote-web_bg.wasm` 3,240,625 B + `Mynoteicon.png` 1,255,457 B（占 28%）。构建链（`rust/apps/web/build.sh`）只有 cargo release（已开 fat LTO + strip，`rust/Cargo.toml:14-17`）→ wasm-bindgen，没有 wasm-opt；图标以原始大图进 dist，而 manifest/主屏图标实际只需要 192/512 两档。
- **建议做法**：① 图标出 192/512 压缩档进 dist，源大图留仓库不发布（预期 dist 直降约 1.1MB）；② build.sh 加 `wasm-opt -Oz` 一道（预期再降 10–20%，须实测并核对功能无回归后固化）；③ verify 加体积预算门：wasm 或 dist 超阈值（如 wasm >3.6MB）报警，防体积悄悄回涨。
- **成本**：小（图标）到中（wasm-opt 需一轮全量冒烟背书）。
- **预期收益**：首载与 SW 缓存更新流量同降约三成；弱网冷开更快（预热优化已把冷开压到 161ms 量级，传输侧是下一个瓶颈）。
- **优先级**：P1。

### D5. editor.rs 6074 行继续拆分；bridge.rs 内嵌 JS 无语法门

- **问题与证据**：`editor.rs` 6074 行仍是全仓最大文件（第八批已列「editor.rs further split」待办，至今未动）；`blocks.rs` 3622 行次之。`editor/bridge.rs` 2003 行的主体是一整段内嵌 JS 字符串常量——改 JS 等于改 Rust 字符串字面量，无 lint、无语法检查，写错只能在浏览器冒烟时暴露（且大文件整文件回写有过截断事故，AGENTS.md 已立外科编辑规矩，拆分能直接减小单次编辑面）。
- **建议做法**：① editor.rs 按既有 editor/ 子模块先例继续拆（标题已拆出 title.rs/title_controller.rs，模式现成）：候选切面为块操作（op_*）、渲染、页面生命周期三组；② bridge.rs 的 JS 抽为独立 `.js` 文件以 `include_str!` 引入，verify 加一节 `node --check` 语法门；③ 拆分只动文件组织、零行为变更，逐拆一提交一全量门禁。
- **成本**：大（多提交串行，每步全量回归）。
- **预期收益**：并行线改同文件冲突面收窄；JS 改动获得语法级即时反馈；后续每批的编辑事故面下降。
- **优先级**：P1。

### D6. 探针/脚本治理：仓库根 317 个 .mjs 无索引

- **问题与证据**：仓库根目录现有 317 个 `.mjs`（probe_/smoke_/dbg_/check_/verify*/round*_ 等混杂），`git status` 约 191 条未跟踪/未提交条目，绝大多数是一次性取证脚本。TESTING.md 未给出现行回归资产索引。新接手者（或新代理）无法分辨哪些脚本是现行守卫、哪些是历史残渣，误删/误跑成本高；根目录噪音也让 git add 逐文件点名（现行纪律）更易出错。
- **建议做法**：一次性治理：现行资产（15 smoke + 关键 probe）留根目录并在 TESTING.md 建索引表（名称/守什么/入口命令）；一次性脚本移入 `archive/probes/` 并整体 gitignore 或一次性提交归档；此后新探针命名带日期/批次，进索引才算交付。
- **成本**：中（分类判断是大头，移动本身机械）。
- **预期收益**：仓库可导航性恢复；并行线的「只加自己的文件」纪律执行成本下降。
- **优先级**：P2。

### D7. i18n 校验加强：现门禁只查键集与残留词

- **问题与证据**：五包 215 键靠手改 JSON。`scripts/verify_rustweb.sh` 第 1 节只查键集一致、第 5 节查已移除概念残留词——查不到三类真实风险：① 值中动态占位（如计数 `{n}`）跨包不一致，运行时才炸；② 代码已不引用的僵尸键长期滞留（删功能漏删键有前科：第七批删 backup.* 漏 settings.backup_meta 一键即同类教训的镜像）；③ 非中文包某值与中文相同（疑似漏译），键集检查完全无感。
- **建议做法**：verify 加第 7 节：占位符跨包一致性、僵尸键扫描（键名全仓引用 grep）、同值疑似漏译清单（只警告不红，给人工裁量）。
- **成本**：小。
- **预期收益**：把文案事故从「用户真机发现」提前到「提交时门禁发现」。
- **优先级**：P2。

### D8. Diag 延伸：无全局错误捕获、回传日志缺环境头

- **问题与证据**：全仓无 `window.onerror`/`unhandledrejection` 到 Diag 的捕获（grep 零命中），未捕获异常只进控制台，用户回传 Diag 时这类错误 invisible；Diag「复制全部」已有（`main.rs:1013-1017`），但复制内容只有日志行，构建戳靠用户另外口头说明（标题线多轮就是靠人工对构建号+日志才定层）。另外 bridge.rs 的 JS 侧只有 1 处 diag::log 对应点，JS 异常目前不回流。
- **建议做法**：① main 启动时装全局错误捕获，异常以 ERR 标签记 Diag（含 message 与 stack 首行）；② 「复制全部」前置环境头：sw VERSION 构建戳、UA、视口尺寸、color-scheme、当前语言包、Diag 行数；③ 桥 JS 侧加一个统一的错误回传口（复用既有 dioxus.send 消息面）。
- **成本**：小。
- **预期收益**：用户每次回传即自带定层信息，省一轮往返；未捕获异常从不可见变可回溯。
- **优先级**：P1。

### D9. 本地提交积压：20 笔未推送、本机单点

- **问题与证据**：`git log origin/main..HEAD` 现为 20 笔（远端停在更早批次），推送依赖用户一次性 PAT 人工通道。积压越久，本机故障/环境退化（已有多次前科）时的丢失面越大；且「远端即备份」这一层目前实际不存在。
- **建议做法**：把推送固化进批次流程：每批部署核对后即走一次推送（PAT 附件模式已跑通多次，流程现成），不攒批；或评估 GitHub 连接器文本推送作日常兜底（已知限制：二进制与删除不支持，大批文本可用、需逐批核对）。
- **成本**：小（流程约定为主）。
- **预期收益**：单点丢失风险收敛到「最近一批」以内。
- **优先级**：P2。
