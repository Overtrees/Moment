## 二、消费方补丁面（详节）

同型特征：机制的归属点不在产出/注册单点，而在每个消费点各补一份判别或清理。今日四案中三案属此型（占位样式漏给呈现者、命中形漏给承载、帧宽协商漏给字段）。

- **A-2 / A-3 是本面最硬的两项**：判别表复制与名单分叉都已有实害或直达落盘面。A-2 的修法模板现成——呈现分支已是单点真源，只差让它顺带产出面型描述；A-3 须先对三张表逐成员做「有意分叉 vs 漂移」对账（本册只能 proven 差异存在，分叉依据 inferred），对账结论写回分类表单点注释，verify 加一条「三消费方派生集 == 登记集」集合断言。
- **A-11** 与今日标题案同型：同一投递动作的收尾清理散在三支且字段组合不一，是「加一支漏一支」型回归的标准温床；收口成本低（一函数三调用）。
- **B-8** 是 Web 侧唯一的消费方补丁：归一函数本身没错，错在只挂了一个消费点。处置前置是产出点枚举——粘贴/插入/转换三条产出路径逐一坐实后才能定前移还是升格 persist 单点，故列待裁而非根治。
- **M-1** 是「代记」变体：日志的消费方代打点。audit_full_e_platform 的 E-05 已登记同批另两处（视频播放失败零行、PDF 导出失败无结果行），根治时一并处理、三处同批收敛。
- **M-2** 是计划与实现的漂移：plan_app_mcp_bridge.md:250 明定抽取为「M2 动工第一步、不是桥的补丁」，grep 证该服务不存在。桥三批已落地并在跑，对账（桥写路径逐命令 × EditorModel 变换）是抽取前置，未对账前不许直接抽——先对账、再决定抽取或登记有意分叉。

## 三、时序 / 遮罩凑数面（详节）

原生侧 asyncAfter/延时命中经逐个判真伪后，**真凑数 8 项（A-1、A-4–A-10、A-12、A-13 中属时序者）**，其余全是设计内语义（防抖、超时、退避、节流——§七排除登记）。共同病根是**缺事件面**：落焦认领、入树等待、在席变更、转场落定四个事件目前都没有单点发布，于是每个消费方各自拿常数轮询/重开/复读兜。

偿还序建议按事件面打包而非逐项打：先立「入树/落定事件面」（A-5 共享工具 + A-1 落焦认领入窗回调 + A-7 预建改挂 completion，三项同源一并落），再立「注册表变更发布」（A-4），A-9/A-10 随手收（同源派生/单点收口）。A-6/A-12/A-13 的常数各有实证动机或已裁口径，列待裁：动它们之前先补「常数与动画/事件同源」的断言锁现状，再议去留。

## 四、断言债面（详节）

量化底数（脚本化普查，非抽样）：verify_ios 70 组、约 1770 处静态断言中，grep 在位类约 1395 处、精确计数类约 378 处，真正编译运行被测代码的 swiftc 表驱动只有 9 处，另有少量 python 实解码/集合运算——**弱断言约占断言点的 75–85%，约 55–60 组以弱断言为主模式**。verify_rustweb 20 节弱节约占 40–50%，其跨源逐值对齐节明显更强。

类型分布：类型 1（字面在位）为绝对主力；类型 2（计数基数）次之，改判沿革最长达九次（C-6）；类型 3（模型自证）现行活例只有 C-9/C-14/C-15 三处半——旧 centerDeviation 式自证已被自觉清除，这点应肯定。**当前主要风险是类型 1/2 的规模效应**：改判注越积越厚，锁的可证伪性越稀释；且历史上 Dynamic Type（C-5）、标题居中（X-3）、签名面（C-13）三次「全绿但真机坏」全部出自此型盲区，每案后新组注释都写明了教训、实现却仍回落到 grep 在位。

## 八、Top 危害五项（最可能再咬人）

1. **C-1 自救组在位锁**（verify_ios [13]/[19]）：自救是用户立的运维纲领（闪退类靠热路径解决、不靠重装），而它的断言只锁字符串在位——guard 真失效时全绿。0.9.44 初始化环事故就是同型盲区打过的脸。这是唯一一项「坏的时候恰好是最需要它的时候」。
2. **A-2 卡片呈现判别整链复制**：已有实害前科（圆角三处漂移真机故障）。呈现分支是高频改动面，每改一次音乐卡/附件卡呈现，拾起几何就静默漂移一次，且无断言拦截。
3. **C-3 桥工具清单三方对账缺失**：桥是主线自办验证的终判通道，清单对账只验「名字在协议文件」——中继或分发任一断链仍绿，等于终判通道本身可静默失效，污染其后所有「桥自办全过」结论。
4. **A-3 原子块型名单三处不一致**：其中 materializeMdTrails 一表直达落盘文档结构，漏改/漂移不报错、只静默改变文档形态，属数据面风险，量级高于一般 UI 漂移。
5. **B-1 HTML 转义四份分叉**：已有实害（导出行高塌陷）。导出是用户数据出仓面，转义口径再漂移一次就是静默坏文档或转义不足，且四份实现使任何一次修口径都必然漏一处。

次席：C-2（拖拽仲裁在位锁）、C-4（场景库登记自证）、A-5（入树重试三写）。
