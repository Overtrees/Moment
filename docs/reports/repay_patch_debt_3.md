## 三、棘轮锁（[73] PD73-1）口径

- 机制：分类器（python）内嵌于 verify_ios.sh [73] 组，对 [73] 标题行之前的全部脚本行逐行分类；[73] 本体不计（截断于首个 `echo "[73]` 行）；整行注释不计。
- 分类规则（与总册 §四 C 类定义同源，首命中定类、一行至多一类，顺序 CNT > FLOOR > 变量捕获 > PRES）：
  - **CNT**（精确计数）：行内含 `$(grep -c…` 或 `$(grep -o…|wc -l)` 命令替换且同行与数字字面量相等比较（`= N` / `="N"` / `-eq N`）；或计数捕获入变量行 `VAR=$(grep -c …`（比较在别行，计 1 点）。
  - **FLOOR**（下限计数）：同上但比较为 `-ge`——门槛语义、非精确基数，只登记不设帽（存量 34）。
  - **PRES**（在位）：行内含 `grep -q` / `grep -qE` / `has` / `hasE` 判定。
- 帽值：CNT ≤ 400、PRES ≤ 1401（= 本批改后同口径实测存量）。纪律：帽只许随存量实降下调；新增弱断言即红，须先升级等量旧弱断言腾位；上调须偿还报告改判 + 用户裁。
- 负对照（全成立）：副本回加一条精确计数断言 → CNT 401 恰红；回加一条在位断言 → PRES 1402 恰红；真文件恰在帽值绿。
- 已知边界（如实）：逐行计点——一行含多个计数表达式只计 1 点（与总册逐断言点口径的差异源，见 §四）；多行续行表达式按物理行计。分类器与帽同在脚本内，防的是「随手回加弱断言」，不防蓄意改帽——后者靠 git 沿革审计。
