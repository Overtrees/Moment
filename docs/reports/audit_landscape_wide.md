# 横屏 / 宽屏全页面 UIUX 审计（2026-11-27，只审未落码）

> 范围：手机横屏（iPhone 横置 852×393pt，宽而矮、左右安全区约 59pt）与大宽屏（iPad 横屏 1180×820pt，含 ≥1288 档注记）两档形态下全部页面。基线 HEAD 477b1bc（0.9.57）。规格真源 = Web 源码（`rust/apps/web`）+ 既往定案。证据分级：proven = 源码量测可算 / inferred = 机制推断 / unknown = 须真机。
> 与「首页竖屏卡间距」线分工：竖屏窄屏 List 行距归该线，本报告只管横屏/宽屏，交叉处引用不重复量测。
> 本报告同时是 `audit_widescreen.md`（E-W1/E-W2，基线 0.9.0/0.9.3）的同题复核：旧项逐项核现行代码后给状态，不整表重报。

## 二、审计面逐项

### 1. 断点与形态切换

- **编辑页宽屏式同构（proven，达标）**：原生 `syncWide`（MomentApp.swift:11142-11146）`(宽≥768 且 高≥600) 或 宽≥1100`，与 Web 媒体串（editor.css:396/631…共 6 处同式；JS 侧 columns.rs:56-61 的 matchMedia 同串）逐字一致。852×393 两边同落单栏、1180×820 两边同落双栏、1100×500 两边同因 ≥1100 条款落宽屏——无分叉点。
- **首页宽屏判定同构（proven，达标）**：原生 `syncHomeSize`（:15817-15819）`宽≥768 || (宽>高 且 高≤560)`、列数 `≥1280 ? 4 : 3`（:15827），与 base.css:371/613 逐项同构（CSS landscape ⇔ w>h、方形归竖屏两边一致）。**非对称落档**（横屏时首页进网格、编辑页仍单栏）是 Web 原口径本身，非原生走样。注：NavState 注释（:15481）仍写旧判定描述，建议随手对齐防误读（零代码风险）。
- **横屏矮高纵向挤压（proven 算式，与 Web 同量级，非缺陷）**：编辑页竖排坞高 = 顶 7 + 头像 72 + gap 6 + 胶囊 66 = 151；正文顶 padding 168。横屏键盘约 216pt 时可见带 177pt、未滚动正文可见 9pt、滚动后紧凑坞（79）下约 98pt ≈ 4 行——Web 坞 + `.editor-pad` 顶 safe+155 同账同量级。坞翻转阈值 `scrollY>30` 无迟滞（:9941），矮高带键盘时紧凑横排近乎常驻、竖排事实不可达；翻转只动悬浮层、正文 padding 恒 168，无内容跳动，与 Web scrolled 驱动同理，判可接受。
- **正文顶 padding 168 vs Web 155（proven，差 13pt）**：原生正文起点更低、无重叠风险；属有意值还是漂移无留痕，建议二选一登记（对齐或定案），列 L-7。
- 完成胶囊 46↔92 顶锚（:10174），横屏底缘 7+92=99 ≪ 393，无需高度钳制，达标。底表面板定高见 §五。

### 2. 安全区（横向）

- **全仓无横向 safe-area 取用代码（proven 代码缺席）**：`safeAreaInsets` 取用仅 `.bottom`（编辑量测 :9063、底表 :8986、备份表 :17860）；页眉横距恒 20（:16031）、编辑页恒 16（:10090）、双栏恒 16（:11198/:11248）。横屏 59pt 扣让全靠 SwiftUI 默认安全区承接——承载侧 EditorHostingController 帧为 nav bounds 全屏（MomentEditorTransition.swift:192），根视图默认尊重安全区，预期编辑页钮左缘 ≈59+16=75、坞以安全区内宽派生自洽（capsuleWidth :10489 以实测 headerW 派生）。
- **Web 侧同为零横向 inset 布局用点（proven）**：Web 全树无 `env(safe-area-inset-left/right)` 布局用点，横屏刘海侧靠视口与固定边距——原生多让 59 属平台正确、非缺陷（audit_safearea_report 口径）。
- **唯一真 unknown 簇**：首页 gridHome 的 ScrollView（:16182）若贴边布局，横屏首列卡左缘仅 24 < 灵动岛 59 区；菜单钳制 `panelLeftX`（:9300-9321）以 geo 全宽坐标、边距只认 12，未叠横向 inset——坐标原点若在安全区内则实际边距 59+12 无问题，若含 inset 区则面板可压进刘海侧。均须真机量测关账（V-1/V-2/V-3）。

### 3. 间距节奏（宽屏）

- **首页网格（proven，达标）**：gap 14 双轴（:16199/:16255）= base.css:375；方卡 aspect 1/1 + radius 26（:16397-16405）；组头整行 + padding 8/−6 与 gap 合成 8（:16216-16232）；空状态整行（:16309）。852 档卡宽 (852−48−28)/3 = 258.7pt（Web 实测 259）；1180 档 (1180−48−28)/3 = 368。
- **L-1 ≥1288 网格框序缺陷（proven，中）**：原生 `.frame(maxWidth: 1240)`（:16246）后 `.padding(.horizontal, 24)`——内距在 1240 **之外**，内容宽 1240；Web 全局 border-box，1240 **含**内距，内容宽 1192。1366 宽时原生卡 (1240−42)/4 = 299.5 vs Web 287.5，每卡 +12pt；且页眉收轴按 (W−1240)/2（:16030）而网格实际缘在 (W−1288)/2，**同轴差 24pt**（D8/W-4 定案被连带打偏）。视口 ≤1288 时两边恰合，故仅 ≥1288 档（iPad 12.9 横屏 1366 等）命中。修复：内距收进框内（padding 先于 frame，或 frame 改 1192），一处修同消同轴差。矩阵行：HOM-15（U5/P4 几何探针可扩此断言）。
- **L-2 independent 双栏净间距 −32pt（proven，中）**：Web independent 在 grid gap `clamp(28,3.2vw,52)` 之外另有左栏 padding-right 16 + 右栏 padding-left 16（editor.css:1006-1011），内容间净距 = gap+32，分隔线在左栏右缘（border-right）。原生以 half=(gap−1)/2 两侧贴 1px 线（:11166-11209，本轮抽核实证），净距恰 = gap、线居中。flow 模式 Web 无栏内距、原生恰合无差。修复：independent 两栏各补 16 内侧 padding、分隔线随左栏右缘；flow 不动。矩阵行：EDT-31/EDT-32（U4b columns_roundtrip）。
- 双栏其余节奏达标：栏距 clamp 本体（:11166）对 Web 最终级联（editor.css:685 覆盖 :640 的 34/4.8vw/72）；栏内块间距 6 与单栏同源；分隔线色已走 border-color 档（T.borderSoft，注释明示，E-W1-4 销账）。
- **图文卡封面宽屏比例达标**：方卡内图文卡底栏 78px 口径已随网格形态落地（E-W2-2 销账）；编辑页内 gallery 宽屏 2 列/366 已对齐（E-W1 旧项，见 §六）。
- **图片页可用区（横向）**：公式无横向显式项，靠安全区隐式承接（inferred）；纵向见 L-4。

### 4. 图片页

- **L-4 可用区纵向公式与 Web 差（proven，低；横屏侧果为底边贴边）**：原生 `ImagePageView`（:18464-18484）`availH = geo.height − 66`、底不让；Web `.img-page-content` 沿用 `.page-content` 节奏（panels.css:155/170）：顶 126、底 40+safeBottom、左右 0。原生纵向多放出约 120pt（顶 66 vs 126、底 0 vs 40+safe）。内部判定与呈现同用 availH 自洽（0.9.34 #4 修复的是判定/呈现不一致，−66 为该修复的落点，本项议的是与 Web 的口径差、非翻旧案）。横屏后果：iPad（safeBottom≈20）大图底边贴屏底、与 D5 定案「页头下可用区」口径不符；竖屏侧顶让不足的页眉压图问题不在本审计范围、仅登记交叉引用。修复提案：availH 改 `geo.height − 126 − (40 + safeBottom)` 对齐 Web，或将 66/0 显式定案为原生偏离留痕，二选一。矩阵行：IMG-03（U5）。
- **L-5 旋转后缩放不复位/不钳制（proven 缺失，效果 unknown，低）**：ImagePageView 无 `onChange(of: geo.size)`（grep 零命中）；ZoomableImageView 的 fit（:3190-3204）只在 zoomScale < base 时抬回、恒调 center——横→竖旋转后旧倍率 > 新 base 时不钳制、旧平移不复位。提案：尺寸变化时重置 zoomScale=base、offset 归零居中。矩阵行：IMG-04（人工终判附带状态读）。
- 标题/返回钮达标：ChromeView 返回钮 46×46 顶 7 横 16（:17037-17062），胶囊总高约 44、底边 53 < 图片区顶让 66 不重叠；标题超 12 字截断单行（:18452-18456），最宽约 236pt，横屏/iPad 均不挤钮。

### 5. 浮层定位与定高

- **斜杠面板（宽屏达标 / 横屏风险 L-3，中）**：宽公式逐项移植 Web（:9530 附近 `min(360, max(220, 内容+12, 视口−24))`，852 宽下 360）；左缘用窗口系 caretX（:3036 convert to nil），双栏右栏天然正确；纵向实测高上翻 + 动态 maxH 优于 Web 固定估高。风险：横屏 393 高下上翻几乎恒触发，锚点靠顶时 maxH = top−22，top=100 时仅约 78pt ≈ 1.5 行内滚——公式 proven、发生率 unknown（V-6）。提案：上翻分支给 maxH 设下限（≥120）并允许覆盖锚点块，与 Web「max-height 320 收缩」口径再对账。矩阵行：EDT-36（U2 P3 slashPanelH，可扩横屏变体行）。
- **菜单类（达标）**：卡片/块菜单 panelLeftX 含 independent 右栏原点修正（:9295-9318；栏宽按 contentW = min(viewW,1440)、gap 同 clamp 派生），宽 216、12pt 钳制、上下翻转同 Web 口径；纵向块菜单高 `min(项数×50+14, 340)` 超出内滚。•••/导出面板宽 246、右 16、顶 59（:10687/:10818）= editor.css:1230；限高 `max(200, viewH−67)`（:10719）vs Web `100dvh−safeTop−64`，横屏差 ≤3pt（注释自登记 ≤8）。钳制坐标系问题见 §二·2（V-3）。
- **底表（达标，L-6 低）**：备份确认底表（:17755-17868）与 Web panels.css:213-219 逐值同（横 14、底 safe+14、maxWidth 600），内容高约 224+2×safeBottom，横屏总占高约 238 < 393。背景色底表（:10508-10602）同式 600 居中；已设背景时内容高约 311+safeBottom，横屏余量仅约 59–80pt（inferred）——不超高但薄。提案：可视高 <500 时色点网格改 8 列 1 行省约 56pt。矩阵行：EDT-38（U4b）。
- **吐司（达标，与 Web 逐值等价）**：Web base.css:657 为左右 16、底 safe+16、**无 max-width**（任务口径中的 600 是确认底表规格、非吐司）。原生两实例（:16143-16175、:17657-17692）同式。横屏物理边距 = 59+16=75/侧、条宽 702；iPad 条宽 1148 全宽——系 Web 口径本身，非原生差；嫌宽须先改 Web 真源。

### 6. 设置族与救援页

- **设置族无统一宽屏容器（proven，结构缺失）**：六页（设置主页/备份/手势/天气/语言/桥设置）靠手抄约定「横 20/顶 126/底 40」逐页一致（:17450/:17650/:17990/:18168/:18380 区段、MomentBridgeSettings.swift:152-155），无一页有数值 maxWidth（grep 命中全为 .infinity）。全仓宽屏收窄只存在于首页列表（1240/1440）与底表（600）。
- **E-1 增强候选（非缺陷，须裁）**：Web 设置页同为全宽无 cap（panels.css:155）——原生全宽 1140 与 Web **等价达标**；天气/桥页表单行长失控是两端同有的问题。若要收窄，属原生增强（D11 路径）：抽 `SettingsContainer`（现约定 + 宽屏 maxWidth 720 居中）六页共用，或先改 Web 真源两端同落。不按 parity 缺陷立项。
- 设置主页滚动可达达标（总高约 969pt 算式 proven，横屏约滚 2.5 屏、iPad 小滚，末行 footer 可达）。版本串为字面量（:17410 区段）——组版 bump 流程每版同步（HEAD 477b1bc 提交信息实证），仅登记脱钩风险、不立项。天气页横屏唤键盘后第二卡可达性 unknown（V-4，两页无显式键盘避让代码、顶距 126 固定）。
- **救援页（MomentRescue.swift:69-241）**：ScrollView 承接、横屏可达性达标（总高约 850pt 算式）；宽屏无限拉宽 1140、statusRow 长摘要折行撑高——E-2 增强候选：宽屏 maxWidth 720 居中（与 E-1 同容器）；WatchdogBar（:427-451，横 16/底 16 无 cap）同加 600 与底表口径齐。本页无显式 safeArea 代码，横屏边距 = 系统让位 + 横 20 ≈ 79（inferred）；背景满铺侧边外 unknown（V-5）。

## 四、修复分批建议

- **批 W-L1（小修组，随下一组版）**：L-1（一处框序）、L-2（independent 两栏各 +16 内侧 padding + 分隔线随左栏右缘，flow 不动）、L-7（168/155 二选一留痕）。三项均为源码可算、断言可锁：HOM-15 扩 ≥1288 卡宽断言、EDT-31/32 扩栏间净距断言。
- **批 W-L2（浮层与图片页）**：L-3（斜杠 maxH 下限 + 与 Web 收缩口径对账）、L-4（availH 公式对齐或显式定案偏离）、L-5（旋转复位）、L-6（bgSheet 矮高 8 列变体）。场景化：EDT-36 扩横屏变体、IMG-03 扩公式断言。
