# 标题胶囊短标题不居中（三修）——占位呈现者定案

- 日期：2026-11-28
- 批次：0.9.66 候选
- 实报：用户 0.9.65 真机——新建无标题篇展示态，胶囊本体在屏幕中央，但标题文字「无标题」贴左、与 meta 行同左缘；用户判读「短字数时标题不居中、只有长文本时才居中」，附截图（本批以该截图为量测对象）。

## 一、机制定案（一句话）

**空标题时胶囊里画的不是字段文本，而是字段的占位串（attributedPlaceholder）；占位串的绘制对齐只认它自带的属性串段落样式，而构造占位串时从没给过段落样式，于是按缺省左对齐绘制——字段的 `textAlignment = .center` 只管字段文本本体，管不到占位串。** 短（或空）时字形块不满行宽，左排与居中的差就是全部余量、肉眼可见；长文本撑满行宽时左右无余量，左排与居中长得一样——这就是「短的偏、长的看不出」的全部原因。

## 二、截图像素量测（本机 PIL 实测，@3x，用户截图原图）

| 对象 | 墨迹/边界（px） | 中心偏差（对胶囊中心） |

| 内容行（胶囊 − 左右内距 20pt） | x∈[486, 692]，宽 69pt | — |
| 标题「无标题」墨迹 | x∈[486, 604]，宽 ≈39.7pt（进距 ≈42） | **−14.7pt** |
| meta「13:14 · 共 0 字」墨迹 | x∈[487, 690]，宽 68pt | −0.2pt（填满行宽，不可分辨对齐） |

推论（几何唯一解）：
- 标题墨迹左缘 486 与行左缘 486 **逐值重合**（+0.00pt）——字形块以行左缘为排版原点，与二修在 0.9.63 截图量到的字段形态签名（−15.3pt、左缘重合）同型。
- 胶囊宽由 meta 定：max(标题进距 42, meta 68) + 41 = 109pt，与玻璃实测 109pt 逐值合——定宽公式无误，坏的只是行内排布。
- 本案与二修案的决定性差别在呈现者：二修案标题是真实文本「使用指南」（字段文本形态）；本案标题为空，字段 text 为空串，画面上的「无标题」是 `TitleTextField.applyFont` 构造的 attributedPlaceholder（`Lang.t("editor.untitled")`）。

## 三、呈现者盘点（源码直读）

展示/编辑两态下胶囊标题行共三个呈现者，各自须自带字形居中指令（Web 基准：`.editor-title-input { width:100%; text-align:center }` 单条指令同管 input 文本与其 placeholder；`.editor-title-meta { text-align:center }`——居中是构造性质，title_controller.rs 文件头注）：

| 呈现者 | 形态 | 居中构造（修前） | 判定 |
|---|---|---|---|
| 截断覆盖层 Text | >10 标量、未聚焦 | multilineTextAlignment(.center) + 满宽帧（一修） | 已修 |
| 字段文本 | ≤10 标量真实文本，两态 | textAlignment .center + 显式满宽帧（二修） | 构造在位（真机终判仍挂二修 §七） |
| **字段占位串** | **标题为空，两态** | **无——applyFont 构造时只有字体/字距/颜色，无段落样式** | **本案坏层** |

占位串构造点全仓唯一（grep `attributedPlaceholder` 仅 TitleTextField.swift:140 一处赋值）。

## 四、二修断言为何逃逸（三层）

1. **量测模型自证**：T24-9 的纯核心 `TitleCapsuleLayout.centerDeviation` 把块原点按居中排布写死（`originX = hPad + (rowW − blockW)/2`），偏差按定义恒 0——它测的是定宽公式与「居中前提」本身，不是呈现。二修报告 §二已自认此病并以结构锁补，但补的锁没覆盖到占位呈现者。
2. **模型把量测串当呈现文本**：`capsuleWidth` 对空标题取 shown = 「无标题」量宽——这是**量测串**；真机上呈现它的是占位串，是另一个呈现者。T24-9 矩阵无空标题格，占位形态从未进入任何断言的视野。
3. **结构锁分工漏第三呈现者**：T24-8 锁字段 textAlignment（文本本体）+ 覆盖层 multiline（覆盖层）；T24-10 锁字段满宽帧（帧宽/放置）。占位串的段落样式无人锁——而它恰是唯一决定占位绘制对齐的属性。

## 五、根治落码（单点）

**TitleTextField.swift · applyFont（占位串构造单点）**：构造 attributedPlaceholder 时新增居中段落样式入串——

```swift
let placeholderPara = NSMutableParagraphStyle()
placeholderPara.alignment = .center
// attributes 增 .paragraphStyle: placeholderPara
```

- 与一修给覆盖层补 multiline、二修给字段补满宽帧同门：每个呈现者在自己的构造点自带显式居中指令，不在消费方打补丁、不给短标题加特判/补距。
- 两态同构生效：applyFont 是占位串唯一构造点，展示态与编辑态（聚焦空标题时占位同样可见）共用，改一处两态齐。
- 胶囊定宽、字段帧、落点映射、meta 行逐字未动；段落样式只影响占位串在字段行内的绘制排布。
- TitleTapCaret.swift 前提注释 P3 同步补第三呈现者与本沿革（纯注释，算式逐字未动）。

## 六、断言（verify [24]）

- **T24-9 补「untitled-placeholder」格**：titleW 42 / metaW 68 / avail 300 → 期望胶囊宽 109、偏差 0。数值与本批截图像素量测互证（胶囊 109pt、meta 68pt）；锁空标题分流的算式面（占位串量宽 + 定宽公式）。
- **新增 T24-11 占位居中机制锁**：applyFont 段（占位串构造单点）内必须有 `alignment = .center` 且经 `.paragraphStyle` 入串——锁的正是本案坏层的属性本身。
- **负对照（本机实做）**：摘除段落样式两行（alignment 行 + .paragraphStyle 行）→ T24-11 判定恰红；复原 → 转绿。T24-9 在摘除下仍绿——反证模型层测不到本缺陷、结构锁不可省（与本批定案 §四互证）。
