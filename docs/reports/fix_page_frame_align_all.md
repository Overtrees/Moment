# 全页面内容框对齐设置页口径：全量盘点与收敛锁

- 裁定：用户 2026-11-28 裁定「其他页除了编辑页、首页外，都要按这个对齐」（承 AUD-C-02 诊断/日志页收窄，扩为全页面口径）。
- 范围：0.9.63 批次，未提交（工作树留主线组版）；本机自检止步，tree 冒烟随 0.9.63 组版统一跑。
- 标准口径（单点，回源实测）：`settingsContentFrame()`（MomentApp.swift `extension View`）= 横 20 / 顶 126 / 底 40 + `wideNarrowClamp()`（`.frame(maxWidth: 720)` + `.frame(maxWidth: .infinity)` 居中）。窄屏（可用宽 < 720）时钳不生效、与手抄逐值等价零变化——此为全面对齐不改窄屏呈现的前提。

## 一、盘点方法与几何前提

- 枚举面 = 导航结构全部整页：根分流（首页/救援）+ ChromeView 页头面 9 页 + 设置子路由 7 页（与 ChromeView 面交叠）+ 自有页头页（日志视窗页）+ 全屏品牌页（开屏）。系统面（PHPicker/分享面板/AVPlayer 承载）非自有页，不入表。
- 量测口径：逐页读其内容容器的修饰链（顶/横/底字面与钳），与标准口径逐值对；各页自持的安全区底距语义逐页单列核对（设置族为平 40、视窗页/图片页为 40 + safeAreaInsets.bottom 的 S7 式自持，两式并存是既定形态、非漂移）。

## 三、豁免与冲突登记

- **图片页（#12）**：其可用区公式（顶让 126、底让 40 + safeBottom、横向全宽供 contain 判定与呈现同源）是既有定案（对齐 Web .img-page-content，审计 L-4 收口）。本批口径只及其页面外框/页头边距：页头为全应用共用 ChromeView（与设置族同形态、全宽）；顶/底让位与标准逐值相同（126 / 40 + 安全区，与视窗页 S7 自持同式）。横向全宽与不设 720 钳属 contain 公式本体，不在本批收敛面——整框顶替会改图判定口径，禁止。结论：外框已对齐（值等价 proven），公式面排除。
- **救援页（#13）**：手抄面核值——横 20 ✓、底 40 ✓、720 框 + 无限宽居中 ✓，与单点逐值等价（proven，MomentRescue.swift 容器尾修饰链直读）。顶距 72 与标准 126 不同：救援页无浮动 ChromeView 页头，标题为内流首行、72 是其自有标题顶距，属壳形态差异、非内容框口径漂移。按工单口径**不改**：不把救援壳改成依赖主应用单点（救援隔离优先，其在主应用初始化失败时须独立可用），手抄留置由 R19-14 单独锁、本批 PF61-3 再加守卫（手抄两值在位 + 对单点零调用）。此差异登记备主线知悉，不属擅改面。
- **日志视窗页（#11）**：与并行批（导出改图标 + 黑卡间距对齐）严格避让，本批零触碰；其内容框现状（值等价 + 共用钳）已由 C-02 落码、DG56-3 在锁，间距终态归该批报告。
- **开屏（#14）**：品牌呈现页（全屏画布 + 独立承载），非内容页，排除。
- 枚举完整性自证：全仓 `ChromeView(` 页头面 9 页、设置 `Sub` 路由 7 页、根分流 2 面、自有页头 1 页（视窗页）、品牌页 1 组，合计与表 14 面一一对应；桥/运维/启动各文件无其他整页 View 结构（grep 普查零命中）；DinoView 为 SVG 图标视图、WatchdogBar 为浮条，均非页。
