## 二、逐项落点

### 1. 「暂无功能使用」行注改为请求后才显示

- 呈现层新增 `PermKind.noteIsNoFeature`（无功能注集合）与 `PermissionsView.showsNote(kind, status)` 谓词，行注渲染经其把关（恰一处）。功能说明注恒显；无功能注文案逐字不动。
- 逐项边界（按各框架状态面定「被请求过」）：
  - 标准授权面（日历/相机/麦克风/相册读/相册存/提醒）：状态进入请求后结果集（已授权/已拒绝/受限制/仅写入）才显；未请求（.notDetermined）与未读到（.unknown）不显。
  - 本地网络：无系统状态面，探针即请求面——未探针（.unknown）不显，探针启动后（检测中/浏览可用/已拒绝/未能确定）显。
  - Face ID：其状态面无未定态（仅可用/不可用），出钮条件「不可用」即未请求等值态（与 showsRequest 同口径）——不可用不显、可用才显。
  - 远程推送：本条初版取舍为「无请求面 → 恒不显」；随后用户追加已声明组归类定规，该行注改写为真实状态说明（见 §二.6），归功能说明注恒显，初版取舍被 supersede，沿革在此登记（代码侧同步移除其集合成员与谓词分支，无残留）。

### 2. 去除请求按钮旁的「未请求」文本

- `trailing` 状态词加单一门：`status == .notDetermined && showsRequest(kind, status)` 时不渲染状态词（标示在位即表意）。已授权/已拒绝/受限制等余状态词逐字不变；`PermStatus` 状态值与状态机零改动，只删这一处呈现。Face ID（不可用）、本地网络（未检测等）的状态词本就不是「未请求」，不在本条范围、不受门影响。

### 3. 副标题文案缩短

- 功能说明四键（通知/定位/实况/后台）五语同步改写：保留「这项权限用来做什么」的要点，删解释性赘述——通知删「与桥设置页同一授权」括注、实况删「在设置中开关」从句（行内图标标示 + 整行深链已承接导航）、定位与后台删与状态词重复的起句成分。对照表见 §三。键数不变（perm 48 键、总 441 键，i18n_deep_check 通过）。

### 4. 实况行「去系统设置」文本去除

- 可见文本删除（随第 5 条图标化一并落）。**深链留存取舍**：深链动作本体不动——实况行整行点按跳系统设置（`rowAction` → `openAppSettings`，PC44-4「深链仅此一类」不破）；呈现面与请求行统一为同一枚引导图标标示；无障碍标签保留「去系统设置」原文（`accessibilityLabel`，非可见文本），VoiceOver 仍可读出行的去向。

### 5. 请求按钮统一改为 SVG 引导图标
