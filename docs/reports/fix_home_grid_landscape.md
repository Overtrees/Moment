## 三、根因定性（proven，机制级）

**`gridCellColumns` 是 eager `Grid`（iOS 16 Grid/GridRow 体系）的跨列 API；`LazyVGrid` 没有列跨越语义，该修饰被静默忽略。** 证据链：① Web/原生设计口径都要求标题全跨，源码里修饰字面在位、断言（旧 F30-6）只锁标题的色/距字面——「作者以为的语义」与「框架实际语义」分叉，正是 AGENTS.md 验证清单第一条的坑型；② 外部实证：SwiftUI 教程与文档口径一致表明 LazyVGrid 无 column span 特性、gridCellColumns 的用例全在 Grid 容器内（本仓编辑器双栏 13556 行的 eager Grid 用法合法、为对照组）；③ 真机形态与「修饰被忽略」逐项吻合：标题退化为 1×1 单元格后，折叠组三件凑一行的布局恰使标题列对齐成第一列（用户原话「标题占了一列」），展开组则标题吃掉首行一格、卡行错位。iPad 与手机**同一机制、同一病**，1366 四列档因组件数（3）与列数（4）互质、散落更明显。

排除项：列数推导（≥1280 四列）本身正确、内容宽账正确、折叠口径与 Web 一致——病不在数值，在结构落点。

## 四、根治落码（结构单点：gridHome 组块化）

落点 `MomentApp.swift` gridHome 一处重构（不在标题视图处打补丁）：

- 全跨元素（只读横幅、公告、组标题、空状态）全部移出 LazyVGrid，置于纵排 `VStack(spacing: 14)`；每组 = 组块 `VStack(spacing: 14) { 组标题; LazyVGrid { 图子列; 文子列 } }`，组内卡片在组网格内连续流排（图/文可同行混排，与 Web 单网格流一致）；新建卡独占一个单格 LazyVGrid（Web 中它同为组头前的一个网格格位）。
- 与 Web 单网格流的等价性：组头在 Web 以 1/-1 强制换行、卡从不在组间混排，故按组切分网格与单网格流的**行构成逐行相同**；纵向间隙逐段同账——块间 14 = Web 行距；组头底 −6 与段距 14 合成距首卡 8；组头顶 = 段距 14 + 头内顶距 8 = 22（Web 行距 + padding-top 同值）。
- 死修饰退役零残留：gridHome 内 `.gridCellColumns` 四处全删（横幅/公告/标题/空状态 gridEmpty 尾）；eager Grid 内的两处合法用法（编辑器双栏）未动。
- 水平账不变：内距 24 先于 1240 框的修饰整体移到纵排（同一修饰序、同一内容宽 1192）；顶占位 135、底距 20、ScrollView 单例（HomeScrollProbe 挂载面）全不变。
- 列数推导单点不变：`syncHomeSize` 公式与 `gridColumns` 消费点原样保留，仅由 F30-19 新锁守恒。
